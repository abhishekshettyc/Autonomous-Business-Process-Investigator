    THE OBSERVABILITY BOUNDARY
    Software needs a signal.
    A general investigation workspace, grounded in evidence you can actually collect.
    01
    Where inputs come from
    Upload CSV/JSON exports from existing monitoring tools, machine software or business systems. Add timestamped operator observations as events. Integrate existing systems through the ingestion API.
    The live demo measures a local software test workload. Our app does not install new sensors or automatically discover equipment.
    02
    When there is only one machine
    Its earlier, known-normal readings become the baseline. The ML model scores later observations against that baseline. Use the same operating mode and measurement units.
    Without enough history, the app requests more data; it cannot learn normal behavior from nothing.
    03
    How physical faults appear
    Existing telemetry may expose temperature, voltage, pressure, error codes or a heartbeat. The app flags unusual values and correlates device events.
    If different faults produce the same signals, the result is a set of hypotheses plus a request for diagnostics or inspection.
    04
    What AI actually does
    Isolation Forest learns patterns in historical numerical readings. A separately reported statistical safeguard catches large single-metric departures. Evidence rules then rank possible explanations and preserve contradictions.
    The detector is ML. Cause ranking is configurable reasoning logic; neither confirms physical damage without supporting evidence.
    Connect through a standard API
    Use POST /api/datasets with a validated JSON bundle, then POST /api/datasets/{id}/investigate. Open API documentation ↗
    The same data contract supports different domains. Domain-specific metric meanings and hypothesis definitions still need configuration.
